ORDENACAO DISTRIBUIDA (MERGE SORT) - 1 CLIENTE E N SERVIDORES.
2o TRABALHO DE PROGRAMACAO PARALELA E DISTRIBUIDA - GRUPO 9.

O PROGRAMA DA ATIVIDADE 1 FOI DIVIDIDO EM DOIS:

  Cliente/  -> FICOU COM A PARTE DE PERGUNTAR O TAMANHO DO VETOR E
               DE DECIDIR DIGITAR OU POPULAR ALEATORIAMENTE O VETOR;
               DIVIDE O VETOR ENTRE OS SERVIDORES, PEDE A ORDENACAO
               DE CADA PEDACO E DEPOIS O MERGEAMENTO DOS PEDACOS.
  Servidor/ -> E O QUE SOBROU DA ATIVIDADE 1: ORDENA O PEDACO RECEBIDO
               PARALELAMENTE (TarefaOrdenadora + rodadas de
               TarefaMisturadora, agora na classe OrdenacaoParalela),
               USANDO OS PROCESSADORES DA MAQUINA ONDE EXECUTA.

SERVIDOR:
  - A main INICIA A THREAD AceitadoraDeConexao E PASSA A ESPERAR A
    DIGITACAO DO COMANDO DESATIVAR, QUE ENCERRA O SERVIDOR (AVISANDO
    O CLIENTE CORRENTE COM UM ComunicadoDeDesligamento, SE HOUVER).
  - A AceitadoraDeConexao ACEITA UMA CONEXAO, INICIA A THREAD
    SupervisoraDeConexao E ESPERA SEU ENCERRAMENTO COM join; POR ISSO
    O SERVIDOR ATENDE UM UNICO CLIENTE POR VEZ. OUTRO CLIENTE QUE PECA
    CONEXAO NESSE MEIO TEMPO FICA AGUARDANDO E E ATENDIDO EM SEQUENCIA,
    DEPOIS QUE O ANTERIOR MANDAR PedidoParaSair.
  - A SupervisoraDeConexao ATENDE AS MENSAGENS (CLASSES QUE HERDAM DE
    Comunicado):
        PedidoDeCapacidade  -> responde Capacidade (no de processadores)
        PedidoDeOrdenacao   -> ordena em paralelo; responde OrdenacaoPronta
        PedidoDeMergeamento -> mergeia 2 vetores; responde MergeamentoPronto
        PedidoDeResultado   -> responde Resultado (contem o vetor resultante)
        PedidoParaSair      -> encerra o atendimento deste cliente

CLIENTE:
  - RECEBE O IP E A PORTA DE CADA SERVIDOR VIA args DA main.
  - PERGUNTA A CAPACIDADE (PROCESSADORES) DE CADA SERVIDOR E DIVIDE O
    VETOR EM PEDACOS PROPORCIONAIS A ELA (EX.: SERVIDORES COM 8 E 4
    PROCESSADORES RECEBEM 2/3 E 1/3 DO VETOR).
  - UMA THREAD ConversaDeOrdenacao POR SERVIDOR, TODAS AO MESMO TEMPO;
    join EM TODAS.
  - DEPOIS, EM RODADAS (COMO NA ATIVIDADE 1), UMA THREAD
    ConversaDeMergeamento POR DUPLA DE PEDACOS, CADA DUPLA MERGEADA POR
    UM SERVIDOR DIFERENTE; join EM TODAS ANTES DA PROXIMA RODADA.
  - AO FINAL, MANDA PedidoParaSair A TODOS OS SERVIDORES E MOSTRA O
    MENU (VETOR INTEIRO, PEDACO DO VETOR, TEMPO).

COMPILAR (UMA VEZ EM CADA PASTA):
    cd Servidor && javac *.java
    cd Cliente  && javac *.java

EXECUTAR (UM SERVIDOR EM CADA MAQUINA; PORTA PADRAO 3000):
    cd Servidor && java Servidor 3000

DEPOIS, NA MAQUINA DO CLIENTE:
    cd Cliente  && java Cliente 192.168.0.10:3000 192.168.0.11:3000

PARA TESTAR NUMA MAQUINA SO, USE PORTAS DIFERENTES:
    java Servidor 3001   /   java Servidor 3002   /   java Servidor 3003
    java Cliente localhost:3001 localhost:3002 localhost:3003

OBS: NAO REPITA O MESMO SERVIDOR NOS args DO CLIENTE (ELE ATENDE UM
CLIENTE POR VEZ, ENTAO O CLIENTE FICARIA ESPERANDO POR SI MESMO); O
CLIENTE RECUSA ESSA SITUACAO. PARA VETORES MUITO GRANDES, AUMENTE A
MEMORIA DA JVM (EX.: java -Xmx4g Cliente ...).
